Session goal: report on where the front-end AI stands, then test the post-exam AI
coaching assessment end to end. Both done. The testing surfaced a **production

## 1. Where the front-end AI actually stands

Measured, not assumed:

- **One runtime AI surface exists**: the post-exam assessment at
  `/mock/result/[attemptId]` → `POST /api/exam/assess` → `src/lib/llm.ts`
  (`gpt-5.4-mini`, JSON mode). Grounded in the attempt's misses, entitlement-gated,
  cached on the attempt, deterministic fallback when the key is absent.
- **Everything else that looks like AI coaching is not.** Practice "Coach Says" is
  `question.explanation`, hard-coded verified content
  (`src/components/quiz/question-card.tsx:81`). Dashboard weak areas / next lesson are
  deterministic (`src/lib/weak-area-cards.ts`). The free readiness result has no AI.
  `/readiness/assessment-demo` is a **static mockup** — zero fetch calls.
- **No chat surface anywhere.** The original intent was a conversational study
  guide; what shipped is a one-shot post-mock report. Partly deliberate: the old
  `/api/ai/explain` rephrase route was removed because per-question runtime AI risked
  inventing legal claims.
- `OPENAI_API_KEY` **is** set on Vercel Production, so the feature works live — but
  before today `exam_attempts` was 0, so no one had ever triggered it.

## 3. ⚠️ The finding that matters most: `/af` serves pre-audit copy from the database

`src/i18n/request.ts` merges `ui_translations` rows over `messages/*.json` at request
time, and **the DB row wins**. All **49** override rows were written 2026-07-17/19 —
before the i18n commits (`848b58e`, `3bdbd9a`, `e05dd48`) and before the 2026-08-04
claims audit. Nothing records which default an override was written against, so there
is no staleness signal.

Verified live on `https://k53coach.co.za/af`:

| Live on /af | Reality |
|---|---|
| "Neem ongeveer **5 minute**" | the free test takes ~1 min |
| "werk **aflyn**" ×2, "installeer as 'n app" | **offline does not exist** — next-pwa deferred |
| **R179** hardcoded (`landing.faqA2`) | bypasses `src/lib/pricing.ts`; JSON uses `{price}` |
| "**VVir** leerders onder 18 moet 'n ouer of voog toestemming gee" (`legal.p3`) | typo **and** the parent-consent claim the audit removed (`profiles.parent_consent` is never read or written) |

**Consequence:** the Stage 1 gate row *"Every claim true ✅"* holds for **`/en` only**.
`CLAUDE.md` has been corrected to say so, and the i18n section now carries the
warning. Commit `e05dd48` is the proof of impact — it edited the JSON and **never
reached users**.

## 7. Two traps worth knowing before you debug anything here

- **rtk filters shell output.** `grep -rl "AI-assessering"` returned **0 matches** for
  a string live in the served HTML of the same running app. It nearly buried the whole
  override finding. Run any grep that *decides* something through **`rtk proxy`**, and
  count with `grep -o | wc -l` — `grep -c` counts lines, which on minified HTML reads
  as 1.
- **Adversarial reviewers were confidently wrong on their worst findings.** Both Grok
  and Codex called the assessment-cache change a HIGH that "breaks every prior paid
  attempt"; the table holds 5 rows and all are fixtures. They did catch two real HIGHs
  the first plan draft missed. Adjudicate every claim against the database.
