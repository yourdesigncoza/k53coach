### Technical notes (dev team)

Morning session (`edc0efc` → `e05dd48`) is summarised above; notes below are the afternoon's QA plus the findings that cut across both.

- **`ui_translations` overrides `messages/*.json` at request time and there is no staleness signal.** `src/i18n/request.ts` → `getOverrides` → `mergeOverrides`. The row wins unconditionally; nothing records which shipped default it was written against. **All 49 rows are Louwrens's** (`updated_by` identical across all), 2026-07-17/19.
- **`e05dd48` — committed today — is the proof case.** It standardised on "proefeksamen", but `nav.mock` carries an override reading "Oefen toets", so the nav is unchanged on `/af`. Note the distinction: `848b58e` and `3bdbd9a` keyed *new* strings, which have no overrides and therefore do land. Only edits to already-overridden keys are shadowed.
- **The claims audit is an `/en`-only guarantee.** `docs/claims-audit-2026-08-04.md` corrected 32 strings in JSON; `/af` still serves pre-audit copy. Verified live: `aflyn` ×2, "5 minute", `R179` hardcoded (bypassing `pricing.ts`, which that very audit introduced), `legal.p3` parent-consent, and the `VVir` typo. `CLAUDE.md` gate row corrected.
- **Do NOT reset the override rows to JSON wholesale.** The first draft of AP-01 classed ~29 as "terminology → reset so JSON wins", which would have reverted a native speaker's Afrikaans in favour of our machine draft. Default inverted: his wording wins unless it asserts something false. Only class-(a) false claims proceed without him.
- **AP-01 → AP-02 ordering is load-bearing.** AP-02's auto-drop treats NULL `default_hash` as stale, so it drops all 49 rows on deploy. Louwrens's approved wording must reach `messages/af.json` **first** or it disappears.
- **AI assessment is monolingual by construction.** `ASSESSMENT_SYSTEM` (`exam-assessment.ts:144`) hard-codes "plain English"; neither the route nor `buildAssessmentPayload` carries a locale. Separately `exam_attempts.assessment` is a single column, so one attempt caches one language — fixing the prompt alone is insufficient. Plan keys on `(locale, promptVersion)`; the version matters or AP-05's prompt changes never reach anyone already cached.
- **A fallback assessment is cached permanently.** The route writes it back regardless of `fallback`, and `if (attempt.assessment)` returns early forever, so a transient outage costs a paying learner the feature with no retry. Clearing the column by hand was the only recovery. 0 such rows exist, so it's a guard not a repair.
- **`parseAssessment` validates shape + href allow-list only** — no step cap, no duplicate detection, no length limits. AP-05's prompt rules would be unenforced requests; extend the validator alongside the prompt.
- **Prose defects from the real generations:** referenced "the exceptions mentioned in the explanation" (leaks our machinery at the learner — constraint 10), duplicated a plan step, aimed a step at a section that had passed, and called a 12/30 section "your best section".
- **26 of 274 approved questions cite law in learner prose** (25 regulation numbers, 1 "Section 65"). Also measured: explanation length is now median 200 / max 671 characters against the documented median 187 / max 397 — that figure was signs-only. AP-06 covers both.
- **`exam_attempts` is now 5 rows, all fixtures** (e2e buyer, via `scripts/e2e/assessment.mjs`). Not usage. `CLAUDE.md` corrected from 0.
- **Harness:** `scripts/e2e/assessment.mjs` — headed, sits a real paper, reads the assembled paper out of `localStorage` (`k53.exam.draft`) to plan a target score per section. Works because scoring is client-side, so the client's paper necessarily carries the answer index, and options are shuffled at assembly so the draft index matches the on-screen order.
- **⚠️ rtk filters shell output.** `grep -rl` returned 0 matches for a string live in the served HTML of the same running app; it nearly buried the override finding entirely. Run any decisive grep through `rtk proxy`, and count with `grep -o | wc -l` — `grep -c` counts lines, which on minified HTML reads as 1. Recorded in `project-gotchas` and the test-run doc.
- **Adversarial review (Grok + GPT-5.6) caught two real HIGHs** the first plan draft missed — AP-02 was detection-only, and the cache needed prompt-versioning. It also produced three confident false positives, both models insisting the cache change "breaks every prior paid attempt" when the table holds 5 fixture rows. Same pattern as 2026-07-24; adjudicate against the database every time.
