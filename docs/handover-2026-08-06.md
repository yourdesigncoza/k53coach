## 2. The free readiness assessment (AP-09) — live

`/readiness` → take the 5-question test → the result page generates a real grounded
coaching read inline. Previously that button pointed at a **static mockup**.

The parts worth knowing before you touch it:

- **Spend control is three independent layers**, none of which needed new
  infrastructure: an HMAC "paper token" naming the ids `/readiness` actually served
  (30-min TTL) → a single-use row in `readiness_assessment_grants` (the insert IS the
  claim; released if generation fails) → a daily cap. Every failure path returns the
  deterministic template at **HTTP 200**, never an error.
- **The cap is derived, not guessed.** Measured 1 440 prompt + 300 completion tokens
  worst case; at published `gpt-5.4-mini` rates that is ~R0.05 a call, so R20/day =
  **400**, in `READINESS_ASSESSMENT_DAILY_CAP`. Re-derive from the
  `[readiness-assess] usage` log lines rather than re-estimating.
- **Answers travel as option TEXT, not an index.** Option order is shuffled per
  sitting, so an index is meaningless against the stored row. This would have
  silently mis-scored every assessment.
- **Nothing is stored server-side.** The sitting is in `localStorage`; the grant row
  is a hash of question ids with no IP, user or answers. Keep it that way.
- **The plan may never point at `/mock`** — it is entitlement-gated, so a step there
  is a paywall dressed as study advice. Asserted in the driver.

`READINESS_TOKEN_SECRET` is set on Vercel Production + Development. Preview is unset
(CLI 53.3.2 loops on `git_branch_required`) and does not need it — previews carry no
Supabase keys, so the template serves there regardless.

## 3. The paid assessment (items 2 and 3) — done, NOT deployed

Three defects, all of which an `/af` buyer felt and an `/en` buyer did not:

1. **One column held one assessment**, so an `/af` view evicted the `/en` one. Now a
   per-locale envelope `{ v: 2, byLocale: { en, af }, attempts }`, keyed on locale
   **and** `PROMPT_VERSION` so prompt fixes reach people who already generated.
   Legacy flat rows are read, not discarded.
2. **The fallback was English whatever the locale.** Now built from `next-intl` keys
   through the same seam the free fallback uses, with an unresolved-key guard and a
   last-resort shape.
3. **A fallback was cached permanently.** Now never written and never counted.

Verified on live data, not just unit tests: attempt `90e7a803` was carrying a
fallback **frozen in production since 2026-08-05**. Opening it regenerated a real
assessment; generating `/af` on the same attempt left both locales intact; re-opening
`/en` was a cache hit with no re-spend.

**AP-05's validator is the other half.** `parseAssessment` used to check shape and
the href allow-list only, so every tone rule was a request the model could ignore —
and the result gets cached and shown to someone who paid. It now enforces, on a
**repair-before-reject** principle: truncate lists, drop duplicate plan steps, drop
focus aimed at a passed section; reject only meta-references ("the explanation"),
runaway lengths, a plan too short after repair, or a bad href. Measured **0
rejections across 8 real generations** — the fallback rate did not move, which was
the stated risk.

## 5. Two things caught by testing that no unit test would have

- **An English sentence leaked into an Afrikaans assessment** — the grounding rule
  handed the model the literal phrase `"review the {section} module"` and it copied
  it verbatim. Reworded; `PROMPT_VERSION` bumped.
- **The e2e drivers were passing on empty pages.** Both looked for controls before
  React hydrated, then measured markup that was already there — one reported a
  "generation" that took 55 ms. Fixed to wait on the API response and on visibility.
  The first production check I ran was green and worthless; assume any driver that
  greens up suspiciously fast is racing hydration.

**An adversarial review (Grok + Codex + Gemini) caught a design error of mine.** I
had the generation ceiling count *failed* generations, reasoning that it bounded
retry storms. It also meant six taps of "Try again" during an outage would lock a
paying learner out of the assessment permanently — the exact defect I was removing,
re-entering through the retry button I had just added. Successes only, now.

## 6b. The Afrikaans sign library — data, not code

**All 373 signs that carry lesson content now have Afrikaans**: 1 914 fields across
`plainEnglish`, `formalMeaning`, `behaviour`, `commonMistake`, `testHint` and
`memoryTrick`. Verified live — every field with English has Afrikaans, no English
lost, and the 31 signs that already had Afrikaans were merged into, not overwritten.

Three things worth knowing before touching it:

- **There is no artifact in the repo.** This was written straight to production over
  the service-role API — no migration, no `scripts/data-repairs/` file. It is not
  reproducible from a fresh clone and not revertible. If that matters, the record has
  to be reconstructed after the fact from the live rows.
- **Terminology was pinned, not re-derived per call.** The failure being fixed was
  drift, so 62 signs across three genuinely templated families (13 speed limits, 22
  parking reservations, 27 supplementary plates) were composed from one translation
  each behind a **per-field exact-match guard** — anything not matching the template
  was reported and hand-translated rather than guessed. That is how `R317` was caught.
  Calque check over the whole corpus returns zero `geen-ry` / `verkeersnetjie` /
  `Voertuigbeheer`.
- **It carries no human sign-off and nothing records that.** Under constraint 9 it is
  unverified content. Unlike the sign names there is no `humanSignOff: false` marker,
  because it was written directly into `content`. Decide how that gets tracked.

**Also repaired: the English on 23 signs.** The `-P` parking family was generated by
substituting a class-plural into a singular frame — "Only park here if your vehicle
is buses", "does not qualify as motorcars", "pedal cycles (bicycles)" four times in
one sign. Rewritten with a guard so only text matching the known-bad template was
touched. Note `R323`, `RM9`, `R126` and `R232` were flagged by the first scan and are
**fine** — "your vehicle is transporting" is correct English.
